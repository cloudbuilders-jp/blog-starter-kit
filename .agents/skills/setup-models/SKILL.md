# setup-models: マルチモデル設定セットアップスキル

`.agents/models.local.yaml`（`.gitignore` 対象）を対話的に作成・更新し、ブログ制作ワークフロー内の各ロールに使うモデルを設定するスキル。

仕様の詳細は [model-routing.md](../../references/model-routing.md) と [models.yaml](../../models.yaml) を参照すること。

---

## 実行ステップ

### Step 1: 現在の設定と利用可能モデルの確認

1. `.agents/models.yaml` と `.agents/models.local.yaml`（存在する場合）を読み込み、現在の設定状態を把握する。
2. 現在の実行環境で利用可能なモデル・プロバイダーを検出する:
   - **T3 Code 環境**: `orchestrator_capabilities` を呼び出して利用可能なプロバイダー・モデル・オプションを取得する。
   - **Claude Code / Cursor / Antigravity 等**: セッション内でサブエージェントに渡せるモデル一覧を確認する。
   - 自動検出できない場合は、利用したいモデル名（およびプロバイダー名）をユーザーに確認する。
3. **未確認のモデルスラッグを推測で書かないこと**（`inherit` は常に有効）。

### Step 2: 構成方針（プリセット）とフォールバック設定の選択

ユーザーに以下を確認する（質問ツールが使える場合は選択式で聞く）:

1. **ベースとなる構成パターン**:
   - **マルチプロバイダー構成（推奨・複数プロバイダー利用可能時）**: 執筆・推敲・検証・並列クロスレビューを複数プロバイダーで分担
   - **単一プロバイダー使い分け構成**: 同一プロバイダー内で上位モデル（執筆・推敲・レビュー）と軽量モデル（PoC 補助など）を使い分け
   - **カスタム構成**: ロールごとに個別に指定
   - **デフォルトへリセット**: 全ロール `inherit`
2. **指定モデルが利用不可だったときの動作（`on_unavailable`）**:
   - `ask`（推奨・既定）: 都度ユーザーへ確認する
   - `fallback_inherit`: 親モデルで自動続行して報告する
   - `error`: 中断する

### Step 3: ロール別モデル割り当ての決定

以下のロールについて、Step 1 で検出したモデルと `inherit` を選択肢に提示して確定する:

| ロール | 用途 | 複数指定（並列パネル） |
|---|---|---|
| `main` | 対話・進行・`NOTES.md` 管理（推奨モデル宣言） | 不可 |
| `poc` | PoC 調査・`poc/` 実装・デバッグ委譲 | 不可 |
| `drafting` | 記事下書きの作成・改稿 | 不可 |
| `polishing` | `yomiyasu` による日本語推敲 | 不可 |
| `review` | 企画・検証・下書きの第三者レビュー共通設定 | **可** |

必要に応じて以下も確認する:
- フェーズ別のレビュー上書き（`ideation_review` / `poc_review` / `draft_review`）が必要か
- モデルごとの推論強度オプション（`effort` / `reasoningEffort` / `thought_level` 等）を指定するか
- 読み取り専用レビューで外部 CLI（`runner: cli` / `cli_runners:`）をオプトイン利用するか（希望する場合のみ CLI の存在確認 `which <cli>` を行う）

### Step 4: 設定内容の確認とバリデーション

書き込み前に、以下を検証してから最終案をユーザーに一覧提示する:

- 指定したすべてのモデルが、Step 1 で確認済み（またはユーザー明示指定）もしくは `inherit` であること
- 複数モデル配列は `review` 系ロールのみに使われていること
- `runner: cli` が読み取り専用ロール以外に割り当てられていないこと
- `.gitignore` に `.agents/models.local.yaml` が含まれていること

### Step 5: `.agents/models.local.yaml` の書き出し

ユーザーの承認を得たら `.agents/models.local.yaml` を生成・更新する。

出力フォーマット例:

```yaml
# Local model routing overrides (git-ignored)
# Generated by /setup-models
version: 1
on_unavailable: ask

roles:
  main: inherit
  poc:
    provider: codex
    model: gpt-6.2-sol
    options:
      reasoningEffort: high
  drafting:
    provider: claudeAgent
    model: claude-opus-5-5
    options:
      effort: high
  polishing:
    provider: claudeAgent
    model: claude-opus-5-5
    options:
      effort: high
  review:
    - provider: claudeAgent
      model: claude-opus-5-5
      options:
        effort: high
    - provider: codex
      model: gpt-6.2-sol
      options:
        reasoningEffort: high
```

書き出し完了後、設定ファイルのパスと適用されたロール一覧を簡潔に報告して終了する。
（`.agents/models.local.yaml` は `.gitignore` 対象のためコミットしない。）
